# teceadraw 活動摸彩系統

員工掃 QR code 用工號報到，投影機上用拉霸動畫抽出得獎人。

- **後台就是 Google Sheet**：名單、獎項、設定、得獎名單、控制台都在裡面，活動當天的操作用「摸彩系統」選單完成。
- **報到頁與前台舞台放在 GitHub Pages**：只有畫面，不含任何資料。
- **資料由 Sheet 綁定的 Apps Script 提供**，以 JSON API 回傳。

完整規格在 [`docs/活動摸彩系統規格書.md`](docs/活動摸彩系統規格書.md)。

```
checkin/      報到頁（員工手機，兼查詢）
stage/        前台舞台（投影，只用鍵盤）；sync.js 是同步模組，stage.css 是版面
gas/          Sheet 綁定的 Apps Script 程式碼
vendor/       QR code 產生程式庫（qrcode-generator，MIT），在本機產生，不呼叫外部服務
tools/        壓力測試與測試名單產生器
docs/         規格書、前台與後台操作小抄、活動前檢查清單
deploy-test/  部署測試（確認 Workspace 允許「任何人」存取）
prototype/    第 0 階段前台視覺原型
```

## 開一場新活動

### 系統管理者

1. 打開範本 Sheet，「檔案 › 建立副本」，存到共用雲端硬碟。Apps Script 程式會一起複製。
2. 副本裡「擴充功能 › Apps Script」→「部署 › 新增部署作業」：
   - 類型：網頁應用程式
   - 執行身分：**我**
   - 誰可以存取：**任何人**
   - 部署時要用 **tecea.org.tw 網域內的帳號**。共用雲端硬碟裡的程式屬於網域，網域外的帳號（例如 gmail.com）可以改程式，但 Google 不讓它部署。
3. 回到 Sheet，「摸彩系統 › 活動前 › 初始化」，貼上部署作業 ID，按「檢查」。系統會用匿名方式實際呼叫一次，確認存取權、部署屬於這份 Sheet、時區、程式版本都正確。
4. 「摸彩系統 › 活動前 › 產生連結」，取得報到連結與 QR code，以及**前台專屬連結**。前台專屬連結內含金鑰，只給前台操作員。
5. 把 Sheet 共用給承辦人與後台操作員（編輯權）。
6. 「檔案 › 設定 › 計算」改成「變更時和每分鐘」，控制台的「最近 10 分鐘錯誤」才會自動更新。

### 承辦人

7. 填人員、獎項、設定分頁，主視覺與獎品照片放進「素材」資料夾 →「摸彩系統 › 活動前 › 資料檢查」。

### 彩排與活動當天

8. 彩排：開始報到 →「進階 › 模擬全員報到」→ 截止 → 鎖定 → 前台實際抽一輪 →「進階 › 清除資料」。順便陪每位後台操作員各按一次選單，完成授權。
9. 活動當天照 [`docs/活動前檢查清單.md`](docs/活動前檢查清單.md) 檢查，然後「活動當天 › 開始報到」。

### 素材檔名

放進「素材」資料夾的檔案，依檔名自動對應，比對時忽略副檔名與大小寫：

| 檔名 | 用途 | 規格 |
|---|---|---|
| `主頁背景` | 主頁背景 | 1920×1080 JPG，小於 3MB |
| `獎項頁背景` | 獎項頁背景 | 1920×1080 |
| `抽獎頁背景` | 抽獎頁背景 | 1920×1080 |
| `logo` | 主頁左上 | 透明背景 PNG，寬至少 600px |
| 跟獎項分頁「照片檔名」相同 | 獎品照片 | 1:1，至少 1000px，小於 2MB |

背景圖要留文字安全區，見規格書 9.2。

## 授權畫面

每個帳號第一次按「摸彩系統」選單時，Google 會跳出授權畫面，這是正常的：

1. 「需要授權」→ 按「繼續」，選自己的帳號。
2. 可能出現「Google 尚未驗證這個應用程式」：這支程式是組織自己寫的，沒有送 Google 審核，所以會這樣顯示。按「進階」→「前往（專案名稱）」。
3. 列出的權限（試算表、雲端硬碟、連到外部網址等）按「允許」。

授權一次之後就不會再出現。彩排時由系統管理者陪每位後台操作員各按一次，活動當天就不會遇到。

## 抽獎原理（白話版）

1. **亂數來源**：瀏覽器內建的 `crypto.getRandomValues`，跟網路銀行加密用的是同一種等級，沒有可以預測的規律。
2. **每人機率相等**：抽獎池裡的 N 個人編號 0～N-1，取一個隨機整數換成號碼。為了避免「取餘數」造成極小的偏差，落在不能整除範圍的亂數直接丟掉重抽（拒絕取樣），所以每個人被抽中的機率剛好都是 1/N。
3. **按下停止的那一刻才決定**：每一次抽獎都按兩下，第一下開始滾動，第二下停下。結果在第二下按下的瞬間決定，立刻存在前台電腦並寫進 Sheet。滾動時閃過哪些名字只是動畫，跟結果無關。
4. **沒有任何旋鈕**：沒有權重、沒有可調參數、沒有「重新洗牌」。每一次都是獨立的新亂數。
5. **每人限中一次**：已中獎和作廢的人都不會再進抽獎池，滾動畫面也只會出現還在池裡的人。
6. **抽獎池在鎖定名單時就固定**：已報到、可否摸彩＝是、登錄狀態不是「移除」的人。控制台會顯示名單版本與檢查碼，前台的版本號跟控制台一致，就代表兩邊用的是同一份名單。

## 前台出狀況時的判斷流程

| 前台畫面 | 原因 | 怎麼處理 |
|---|---|---|
| 右下角「離線中，待同步 N 筆」 | 網路斷了 | **繼續抽，不要關掉前台**。結果存在這台電腦，網路恢復後自動補寫進 Sheet。 |
| 主頁按 → 顯示「名單載入中」很久 | 前台連不到後台 | 先看網路。網路正常的話，用「初始化」檢查部署（可能被封存或版本太舊）。 |
| 整個畫面「後台程式版本太舊」 | 部署還是舊版本 | 系統管理者：管理部署作業 → **編輯現有部署** → 版本選最新。 |
| 整個畫面「另一台前台作用中」＋4 位數代號 | 同時開了兩台前台 | 要由這台接手：後台「活動當天 › 強制切換前台」輸入代號。不接手就關掉這台。 |
| 整個畫面「前台連結已失效」 | 前台連結被重新產生，或活動已結束 | 後台重新「產生連結」，給前台新連結。 |
| 上方紅色提示「獎項在鎖定後被修改」 | 鎖定後有人改了獎項分頁 | 還沒開抽：後台解除鎖定 → 重新鎖定 → 前台回主頁按 F5。已經開抽：不能解除鎖定，把獎項分頁改回原樣，警告會自己消失。 |
| 上方紅色提示「名單已更新」 | 後台重新鎖定過 | 前台回主頁按 F5。 |
| 前台電腦當機或故障 | — | 備用電腦開前台專屬連結 → 畫面顯示接手代號 → 後台強制切換。進度會從 Sheet 恢復。 |
| 斷網又當機 | 這台的待同步結果還沒寫進 Sheet | 等網路恢復後重開同一台，結果會補上。來不及等就用備用電腦接手，原本那台的結果會被拒絕，控制台「舊前台補寫被拒」會變紅，以台下看到的結果人工補登。 |
| 按鍵沒反應 | 視窗沒有鍵盤焦點，或動畫正在進行 | 右下角有小灰點就點一下畫面；動畫進行中按什麼都不會有反應。 |

## 更新程式

1. 改完程式，把 `gas/Common.gs` 的 `BUILD` 加一。
2. 把 `gas/` 的檔案貼進 Apps Script，或用 clasp 推送。
3. **已經開著的 Apps Script 編輯器分頁要先重新整理**。舊分頁只要一存檔、執行函式或改部署，就會把新程式蓋回舊的。
4. 「部署 › 管理部署作業」→ 選**原本那一個**部署 → 鉛筆圖示 → 版本選「新版本」→ 部署。
   - **不要按「新增部署作業」**：新部署會有新的 ID，Sheet、報到 QR code、前台連結都還指向舊的。
   - 不要封存原本的部署。
5. Sheet 選單「活動前 › 初始化」按一次「檢查」，確認沒有「部署的版本比目前的程式舊」的提醒。
6. 選單或控制台有變動時，在編輯器執行一次 `setupTemplate`。它只會重建控制台，其他分頁的資料不會動。

前端（`checkin/`、`stage/`）推上 GitHub 後，GitHub Pages 一兩分鐘內會更新。

### 建立範本（第一次）

1. 在共用雲端硬碟新建一份 Sheet，「擴充功能 › Apps Script」。
2. 專案設定：時區選 (GMT+08:00) 台北，勾選「在編輯器中顯示 appsscript.json」，貼上 `gas/appsscript.json`。
3. 依檔名建立 `gas/` 底下每個檔案（`.gs` 新增「指令碼」、`.html` 新增「HTML」，名稱不含副檔名），內容整份貼上。
4. 在編輯器執行 `setupTemplate`，完成授權，回 Sheet 重新整理。

## 壓力測試

需要 Node 18 以上。

```bash
node tools/make-test-people.mjs 600 > test-people.csv
```

Windows PowerShell 的 `>` 會存成 UTF-16，壓測讀不到工號，請改用：

```powershell
cmd /c "node tools\make-test-people.mjs 600 > test-people.csv"
```

1. 把 `test-people.csv` 的內容（不含標題列）貼到「人員」分頁 A2。工號欄要是純文字格式。
2. 「摸彩系統 › 活動當天 › 開始報到」。
3. 執行（`--e` 是部署作業 ID）：

```bash
node tools/stress-test.mjs --e <部署作業ID> --csv test-people.csv --n 300 --window 30
```

驗收標準：30 秒內送出 300 人，全部在 60 秒內成功，「回報已報到」為 0。逐筆耗時寫在 `stress-result.csv`。跑完用「進階 › 清除資料」回到準備中。

### 部署測試

新的 Workspace 第一次使用前，先確認可以用「任何人」部署：在共用雲端硬碟建一份空白 Sheet，貼上 `deploy-test/Code.gs` 部署，用手機無痕視窗開 `deploy-test/test.html?e=<部署作業ID>`，GET 與 POST 都要出現 ✅。「誰可以存取」選單裡沒有「任何人」，代表 Workspace 管理員關閉了這個選項。

## 前後端版本相容

`config` 會回傳 API 版本號，前端發現不相容時顯示「此活動需使用 /vN/ 網址」。API 有不相容的改動時，把當時的 `checkin/`、`stage/`、`vendor/` 複製到 `v1/` 資料夾保存，設定分頁「前端網址」改成 `…/teceadraw/v1`，舊活動就能繼續用舊前端。
