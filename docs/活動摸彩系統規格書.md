## 1. 目標與範圍

一套可重複使用的活動摸彩系統：

- **報到**：員工掃 QR code，用工號報到；同一頁也用來查詢自己的報到狀態。
- **後台**：就是那份 Google Sheet。資料管理、活動當天的操作、狀態監看都在 Sheet 裡完成，沒有另外的後台網頁。
- **前台**：投影用的簡報式舞台畫面，名字以拉霸動畫抽出；作廢與補抽也在前台操作。
- **可複用**：其他活動由系統管理者複製範本 Sheet、完成部署與初始化即可使用，不需要改程式碼。

**設計前提：** 部署、初始化、測試、設定由懂 GAS 的系統管理者負責；**活動當天操作 Sheet 與前台的人不懂 GAS**，所以當天會碰到的操作一律以「直接在 Sheet 打字」「按選單」「按鍵盤」完成，不需要理解系統內部。

**不在範圍內：**

- 獎項價值與扣繳計算
- 即時匯出功能（得獎名單直接列印 Sheet）
- 紙本券核對（由現場人員處理）
- 抽獎用 MP4 動畫
- **網路全面中斷時的備案**：現場自行改用紙本方式進行，系統不處理
- **已離開前台的獎項事後發現問題**：沒收獎品、不補抽，由承辦人在得獎名單「備註」欄人工註記，系統不處理
- 個資的保存期限管理與自動刪除
- 演練模式（彩排直接用正式流程跑，跑完一鍵清除，見 6.4）

## 2. 系統架構

```
GitHub Pages（steven 個人帳號，公開 repo `weiquarter/teceadraw`）── 只放畫面，不含任何資料
 ├─ /checkin   報到頁（員工手機，兼查詢）
 └─ /stage     前台舞台（投影，16:9，1920×1080）
        │ fetch（網址參數 ?e=<GAS 部署 ID> 決定連到哪一場活動；
        │        前台另帶 &k=<前台金鑰>）
        ▼
GAS Web App（由 wei@tecea.org.tw 部署，存取權「任何人」，執行身分「我」，時區 Asia/Taipei）
 ── 部署必須用 tecea.org.tw 網域內的帳號：Sheet 放在共用雲端硬碟，綁定的 GAS 屬於網域，
    網域外帳號（例如 gmail.com）可以改程式、建版本，但 Google 不允許部署
 ── 報到與前台用的 JSON API、LockService 寫入保護
        │
        ▼
Google Sheet（資料庫兼後台）
 ├─ 一般分頁：人員、獎項、得獎名單、設定、控制台、Log
 ├─ 「摸彩系統」選單：需要系統檢查的動作（以操作者本人的 Google 身分執行）
 └─ Drive「素材」資料夾（主視覺、獎品照片）、「備份」資料夾
```

### 2.1 技術決策與理由

| 決策 | 理由 |
|---|---|
| 資料放 Google Sheet＋Drive | 組織內的人都熟悉，資料歸組織所有，交接方便 |
| 後台就是 Sheet，不做後台網頁 | 存取權直接用 Sheet 共用設定控管，不需要密碼；當天操作員只要會用 Sheet |
| GAS 只當 API，不產生畫面 | GAS HtmlService 包在 iframe 裡，載入慢、動畫容易卡頓 |
| 前端放 GitHub Pages | 靜態網頁載入快；600 支手機同時開啟也不會增加 GAS 負擔 |
| 前台在本機計算抽獎結果 | 台上零延遲，斷網也能繼續抽 |
| 每抽出一位就立即寫回 Sheet | 換任何一台電腦打開前台連結，都能從 Sheet 恢復進度 |
| 不使用任何時間驅動觸發器 | 所有 GAS 執行都由人的操作引起，出錯時當下就知道，不會在背景默默失敗 |
| 不做 Service Worker 離線快取 | 容易發生「快取卡住舊版」的維護問題；改用本機儲存進度＋攔截 F5＋預載素材（見 7.4） |
| QR code 在本機產生 | 不把網址送給第三方 QR 服務，也不怕那些服務停用 |
| 每場活動手動部署 GAS | 由系統管理者執行；初始化時提供步驟清單並自動檢查部署是否正確 |
| 報到先記錄、再批次寫入 Sheet | 實測同一份 Sheet 逐筆讀寫的上限約每秒 10 筆，尖峰時會排隊並占滿 GAS 同時執行名額；改成先記錄在 Script Properties，由空著的請求一次補寫（見 5.4） |
| 前台只用鍵盤 | 避免前台操作員誤觸滑鼠就抽出一位（抽出不能退回） |

### 2.2 資安原則

- repo 公開，但**程式碼裡不含任何員工資料或金鑰**。
- **整套系統沒有密碼**，存取權全部跟著 Sheet 的共用設定走：
  - 後台操作：從 Sheet 選單執行，Google 會自動確認操作者有這份 Sheet 的編輯權。
  - 前台：使用 Sheet 選單「產生連結」產生的**前台專屬連結**（內含隨機金鑰），只有能打開 Sheet 的人拿得到。懷疑外流時，選單「重新產生前台連結」，舊連結立即失效。
- 不需要金鑰的公開 API 只有：`config`、`lookupId`、`checkin`。
- 公開 API 有開放時間：依系統狀態回應（見 5.2），「結束活動」後全部不回傳資料。
- 已知且接受的風險：報到期間有人可用程式逐一試工號，取得「單位＋遮蔽姓名」清單。GAS 看不到呼叫者 IP，無法針對單一來源限速，所以用開放時間縮小暴露窗口。
- 「人員」「獎項」分頁使用**警告模式保護**（改動時跳出提醒，但編輯者仍能修改）。不用硬性保護，因為選單動作以操作者本人身分執行，硬性保護會連選單都寫不進去。
- 前台金鑰存在 GAS 的 Script Properties，不寫在 Sheet 儲存格裡。

## 3. 角色與裝置

| 角色 | 懂 GAS | 裝置 | 使用 | 職責 |
|---|---|---|---|---|
| 系統管理者 | 是 | 任一電腦（壓測需裝 Node.js） | Sheet、Apps Script | 複製範本、部署 GAS（須用 tecea.org.tw 帳號）、初始化、壓力測試、彩排準備、陪操作員完成選單授權 |
| 承辦人 | 否 | 任一電腦 | Sheet | 匯入名單和獎項、設定活動名稱與提示文字、列印得獎名單、人工備註 |
| 後台操作員（當天） | 否 | 開著 Sheet 的電腦 | 控制台、選單、直接改儲存格 | 開始／截止報到、鎖定名單、指定下一個獎項、監看前台、現場新增與移除人員 |
| 前台操作員（當天） | 否 | 前台電腦（接投影機），鍵盤 | /stage | 跟著主持人的口令換頁、抽獎、作廢、補抽 |
| 員工（約 600 人） | 否 | 自己的手機 | /checkin | 報到、確認自己的報到狀態 |

前台和後台是**兩台不同的電腦**，各由一人操作。前台操作員不在台上。主持人、前台、後台三人之間的溝通方式（耳機、手勢、LINE）由現場決定，系統不處理。

**授權：** 每個帳號第一次按「摸彩系統」選單時，Google 會跳出授權畫面。彩排時由系統管理者陪每位後台操作員各按一次、完成授權，活動當天就不會遇到。控制台也放一行提示「第一次使用選單時會要求授權，屬正常現象」。

## 4. Google Sheet 結構

### 4.1 人員

| 欄位 | 說明 | 由誰填 |
|---|---|---|
| 縣市 | 只用於篩選統計，不顯示在任何畫面 | 承辦人 |
| 部門 | 只用於篩選統計，不顯示在任何畫面 | 承辦人 |
| 單位 | 報到與前台顯示用 | 承辦人 |
| 工號 | **整欄預設純文字格式**（保留前導 0） | 承辦人 |
| 姓名 | | 承辦人 |
| 可否摸彩 | 下拉選單：是／否 | 承辦人 |
| 登錄狀態 | 下拉選單：既有／現場新增／移除 | 承辦人、後台操作員 |
| 報到時間 | 空白代表未報到；報到尖峰時可能比手機上的「報到成功」晚幾秒才出現（見 5.4） | 系統（後台操作員可手動清除或填入） |
| 中獎獎項 | | 系統 |

**登錄狀態的行為：**

| 登錄狀態 | 報到頁 | 抽獎池 |
|---|---|---|
| 既有 | 正常 | 已報到＋可摸彩就進池 |
| 現場新增 | 正常 | 同上 |
| 移除 | 「查無此工號，請至報到處」 | 不進池（就算已報到） |

- 登錄狀態空白一律當作「既有」處理，資料檢查會提醒補填。
- 登錄狀態在鎖定名單前修改都有效；鎖定後修改不影響已鎖定的抽獎池，要生效須先解除鎖定。

**當天的操作方式（都是直接在 Sheet 打字）：**

| 要做的事 | 怎麼做 | 時機 |
|---|---|---|
| 現場新增人員 | 在**最下面**加一列，填單位、工號、姓名、可否摸彩，登錄狀態選「現場新增」，然後請他自己掃 QR code 報到 | 報到中 |
| 截止後才新增的人 | 同上，再由操作員在報到時間欄按 `Ctrl + Shift + ;` 填入目前時間 | 截止後、鎖定前 |
| 移除人員 | 登錄狀態改成「移除」，**不刪列** | 鎖定前 |
| 取消報到（幫錯人報到） | 清掉該列的報到時間 | 鎖定前 |
| 找人 | 用篩選，**不排序** | 隨時 |

**操作三原則（寫進操作小抄）：不刪列、不排序、新增一律加在最下面。** 報到寫入時一律依工號欄重新找列，排序不會讓資料寫錯位置（已用 600 人全部打亂順序實測驗證）；三原則保留，是為了讓操作習慣單純：

- 不刪列：要移除的人改登錄狀態為「移除」。被刪掉的人如果剛好在那幾秒內報到，報到時間會寫不進去，Log 記一筆「人員分頁找不到這些工號」。
- 不排序：找人用篩選就好，排序本身不會出錯，但會讓其他人找不到原本的位置。
- 新增加在最下面：維持名單順序，方便核對。

**讓直接打字不容易出錯的預設：**

- 工號整欄預設純文字；可否摸彩、登錄狀態整欄預先套好下拉選單，新加的列自動套用。
- 現場新增的人：報到頁查不到工號時，系統會重新讀一次人員分頁，所以剛打進去的人馬上查得到。為了避免有人亂試工號一直觸發重讀，限制每 10 秒最多一次；新增後馬上掃碼仍顯示查無此工號時，等幾秒再試即可。
- 「開始報到」後本分頁加上警告模式保護。

### 4.2 獎項

| 欄位 | 說明 |
|---|---|
| 排序 | 數字，預設的抽獎順序 |
| 獎項名稱 | |
| 數量 | 1～10（超過 10 份時，人工拆成兩個獎項） |
| 照片檔名 | 對應「素材」資料夾裡的檔案；比對時忽略副檔名與大小寫；空白＝無照片版面 |
| 抽法 | 下拉選單：一次抽完／逐個抽出 |
| 狀態 | 系統填寫：未抽／進行中／已完成 |

- **截止報到前**可直接在此分頁新增、修改獎項（含臨時加碼），照片直接放進「素材」資料夾。這段期間系統不寫入本分頁，直接修改沒有衝突。
- 「截止報到」時自動做一次獎項資料檢查，問題列在控制台，但不擋截止。
- 「鎖定名單」時獎項與名單一起凍結（加警告模式保護，並記錄檢查碼）。鎖定後若獎項被修改，控制台顯示「獎項在鎖定後被修改，請解除鎖定後重新鎖定」，前台拒絕抽獎。

### 4.3 得獎名單

| 欄位 | 說明 |
|---|---|
| 時間 | 抽出時間 |
| 獎項 | |
| 名額序號 | 該獎項的第幾格 |
| 單位、工號、姓名 | |
| 狀態 | 有效／作廢（由前台寫入） |
| 備註 | 系統寫「補抽」；其他由承辦人人工填寫（例如事後沒收獎品） |

- 作廢的列以條件式格式自動加刪除線。
- 列印前按選單「整理得獎名單」：依獎項排序、作廢的列排到最後。之後直接按 **Ctrl+P** 即可列印（標題列已凍結、欄寬已設定）。

### 4.4 設定

| 項目 | 說明 |
|---|---|
| 活動名稱 | 例如「2027 春酒」，所有畫面都從這裡讀取，系統不寫死任何字眼 |
| 副標題 | 例如日期、地點 |
| 配色主題、字型、拉霸樣式 | 見第 9 節 |
| 進階色碼 | 主色、輔色、背景色、文字色，空白＝用配色主題 |
| 提示文字 | 報到成功、具抽獎資格、無抽獎資格、報到已截止、查無工號、系統準備中、活動已結束、請截圖，各一列，都可以自訂 |
| 前端網址 | 預設 `https://weiquarter.github.io/teceadraw`，fork 自架時才需要改 |

### 4.5 控制台

活動當天後台操作員主要看這一頁，**只有一個儲存格可以改**（下一個要抽的獎項），其他全部自動更新。

| 區塊 | 內容 |
|---|---|
| 目前狀態與下一步 | 例如「目前：報到中 → 下一步：活動當天 › 截止報到」，用大字顯示 |
| 報到統計 | 已報到／總人數／有抽獎資格且已報到的人數（不含「移除」） |
| 名單快照 | 版本號、抽獎池人數、檢查碼 |
| 下一個要抽的獎項 | 預設照排序；**可從下拉選單改選**，前台回主頁時生效 |
| 前台監看 | 前台代號、目前獎項與頁面、待同步筆數、最後回報時間（超過 15 秒標紅＝前台可能離線） |
| 即時得獎名單 | 目前獎項的得獎人與作廢狀態 |
| 錯誤監看 | 最近 10 分鐘 GAS 錯誤次數 |
| 資料檢查結果 | 截止／鎖定時的檢查問題清單 |
| 提示 | 「第一次使用選單時會要求授權，屬正常現象」 |

前台專屬連結**不顯示在控制台**，只在選單「產生連結」的對話框裡出現。

縣市、部門的統計由使用者自行對人員分頁篩選，控制台不另外拆分。

控制台的公式引用其他分頁，建立範本時要最後才建控制台；先建的話公式會指向還不存在的分頁，報到統計會一直算錯（第 1 階段實際發生過）。「最近 10 分鐘錯誤」依賴 Sheet 設定「檔案 › 設定 › 計算：變更時和每分鐘」，共用雲端硬碟的 Sheet 無法由 GAS 設定這一項，要手動或用 Sheets API 設定。

### 4.6 系統分頁（隱藏）

`_系統`（系統狀態、部署 ID、素材與備份資料夾 ID）、`_前台狀態`、`_名單快照`、`_操作紀錄`。控制台以公式讀取 `_系統` 的系統狀態。

### 4.7 Log

記錄**所有錯誤**與**所有前台、選單操作**（抽出、作廢、鎖定等）。`checkin` 成功不記（人員分頁的報到時間就是紀錄），避免報到尖峰時寫入次數加倍。壓力測試的逐筆耗時由壓測腳本自己記錄，不寫進 Log。

| 欄位 | 說明 |
|---|---|
| 時間 | |
| API／動作 | 例如 `checkin`、`recordDraw`、`鎖定名單` |
| 結果 | 成功／失敗 |
| 耗時（毫秒） | |
| 對象 | 工號或獎項 |
| 前台代號 | 前台的呼叫才有 |
| 錯誤訊息 | |

## 5. 報到（手機）

### 5.1 報到流程

1. 員工在報到處完成紙本簽到、領取領獎券，入場後掃桌上的**固定 QR code**，打開報到頁。
2. 輸入工號。輸入時自動去掉空白、全形轉半形、英文轉大寫（Sheet 裡的工號建立對照表時也做同樣處理）。
3. 確認畫面：
   ```
   王○明（業務部）
   ✓ 具抽獎資格        ← 或顯示自訂的「無抽獎資格」提示文字
   [ 確認報到 ]  [ 不是我，重新輸入 ]
   ```
4. 按「確認報到」→ 完成畫面（適合截圖）：
   ```
   ✅ 報到成功
   2027 春酒
   王○明（業務部）
   報到時間 18:02
   具抽獎資格
   請截圖保存
   ```

- 姓名一律遮蔽顯示，括號內只顯示單位。
- 截圖只讓員工安心用，系統與現場都不把它當作憑證。
- **報到頁兼查詢**：不確定有沒有報到成功的人，再掃一次 QR code、輸入工號即可，不另做查詢頁。

### 5.2 各種狀況的畫面

| 系統狀態／狀況 | 畫面 |
|---|---|
| 準備中 | 「系統準備中」，不接受報到 |
| 報到中：正常報到 | 確認畫面 → 完成畫面 |
| 報到中：重複報到 | 「您已於 18:02 完成報到」＋抽獎資格，畫面同樣適合截圖，不重複寫入 |
| 查無此工號、登錄狀態為移除 | 「查無此工號，請至報到處」 |
| 已截止之後：已報到的人 | 照常顯示報到時間與抽獎資格 |
| 已截止之後：未報到的人 | 「報到已截止」（不顯示姓名） |
| 已結束 | 「活動已結束」，所有公開 API 不再回傳資料 |

### 5.3 等待與失敗的畫面

| 經過時間 | 畫面 |
|---|---|
| 0～3 秒 | 按鈕變成轉圈＋「報到中…」 |
| 3 秒後還沒回應 | 加一行「人潮較多，正在為您排隊，請勿關閉此頁面」 |
| 失敗自動重試中 | 文字不變，背景以隨機間隔（1～3 秒起，逐次拉長）重試，最多約 30 秒 |
| 30 秒仍失敗 | 「目前連線不穩，請稍後重新掃描 QR code」 |

- 請求一旦送到 GAS 就會執行完，員工中途關閉頁面不影響報到寫入；重掃會看到「已報到」。
- 不使用瀏覽器的「確定要離開嗎」跳窗（LINE、FB 內建瀏覽器支援不穩定）。
- 每次請求最多等 15 秒；放棄前的總時間實測約 24～28 秒。

### 5.4 效能設計與目標

**目標：30 秒內 300 人掃碼，全部在 1 分鐘內成功報到。**（涵蓋「主持人喊一聲大家一起掃」的最壞情況）

GAS Web App 以「執行身分：我」部署時，所有請求算在部署帳號一人頭上，同時執行上限約 30 個（推測：依 Google 配額文件的既有知識，未查證原文；壓測結果與這個數字吻合）。一位員工完整報到會呼叫 3 次 GAS（`config` → `lookupId` → `checkin`），設計如下：

| 呼叫 | 做法 | 實測中位數（300 人 30 秒） |
|---|---|---|
| `config` | 讀 CacheService | 約 1.0 秒 |
| `lookupId` | 「工號 → 遮蔽姓名、單位、資格、登錄狀態」對照表放 CacheService（超過 100KB 時切塊存）；查不到時重讀人員分頁（每 10 秒最多一次） | 約 1.1 秒 |
| `checkin` | 用快取與待寫入清單判斷是否已報到；未報到就把報到時間記在 **Script Properties**（`p:<工號>`）並立刻回應，不碰 Sheet | 約 5.4 秒 |

**批次寫入 Sheet：**

- 每個 `lookupId`、`checkin` 結束前，若有待寫入的報到、而且 Script Lock 空著（`tryLock(0)`，拿不到就略過不等），就由這個請求把**所有**待寫入一次寫進 Sheet，寫完若又有新的進來，最多再接著寫兩輪。
- 寫入時讀一次工號欄，**依工號重新找列**，不依賴記住的列號；該列已有報到時間就不覆寫。寫完才從待寫入清單刪除，中途失敗下次會重寫，結果相同。
- 「截止報到」切換狀態前，先把待寫入全部寫完；「清除資料」會一併丟棄待寫入。
- Script Properties 是持久儲存，GAS 執行中斷也不會遺失已回應「報到成功」的紀錄。

**實測結果（第 1 階段）：**

| 測試 | 結果 |
|---|---|
| 逐筆寫入版本，300 人 30 秒 | 299 / 300 成功；Sheet 寫入上限約每秒 10 筆，`checkin` 中位數 7.6 秒，1 人因同時執行名額占滿而在 `config` 失敗 |
| 批次寫入版本，300 人 30 秒 | 300 / 300 成功，0 失敗，無重複寫入；每人總耗時中位數 7.8 秒、最慢 27.9 秒 |
| 批次寫入版本，人員分頁 600 人全部打亂順序後，600 人 60 秒 | 600 列全部寫在正確的列，0 失敗、0 重複、Log 無錯誤 |

- 會動到整張表的動作（鎖定名單、選單操作、重建對照表、批次寫入）才使用 LockService。
- 一位員工從輸入工號到看見結果約 7～15 秒，畫面在 3 秒後會顯示「人潮較多，正在為您排隊」。實際報到通常分散在數分鐘內，不會這麼集中。
- 備案（先不做）：要再加速時，把 `config` 合併進 `lookupId`（每人少一次呼叫），或把批次寫入集中給少數請求處理、減少逐筆刪除待寫入清單的次數。

### 6.3 彩排

不另設演練模式，彩排直接走正式流程：

1. 開始報到 → 用手機實際報到幾筆，或「進階 › 模擬全員報到」
2. 截止報到 → 鎖定名單 → 前台實際抽獎、作廢、補抽、回看
3. 跑完後「進階 › 清除資料」，回到準備中

彩排期間報到頁會正常接受報到，所以彩排請在報到 QR code 對外公布之前進行。

### 6.4 清除資料（一鍵重來）

- 位置：「進階 › 清除資料」，需要輸入確認字串（例如「確定清除」）。
- 清除範圍：報到時間、中獎獎項、得獎名單、前台狀態、名單快照、操作紀錄；系統狀態回到「準備中」；前台需重新開啟。
- **不會清除**：人員名單、獎項、設定、Log。
- 對話框內有「清除前先備份」勾選框，預設勾選；勾選時把整份 Sheet 複製一份到「備份」資料夾，檔名帶日期時間。彩排時可以取消勾選，避免備份堆積。

## 7. 前台舞台

### 7.1 頁面流程

```
主頁 → 獎項頁 → 抽獎頁（名字滾動）→ 停下公布（同一頁）→ 回主頁 → 下一個獎項…
         ↑
主頁按 ← 可回看已完成的獎項（見 7.5）
```

| 頁面 | 內容 |
|---|---|
| 主頁（報到期間） | 主視覺、活動名稱、報到 QR code（本機產生）、即時報到人數 |
| 主頁（截止後） | 主視覺、活動名稱 |
| 獎項頁 | 獎品照片、獎項名稱、數量、抽法標籤 |
| 抽獎頁 | 上方顯示獎項名稱，中間的格子滾動名字（名額有幾份就有幾格） |
| 公布 | 名字停在格子裡，同一個獎項的得獎人都留在同一頁 |
| 回看 | 已完成獎項的公布頁，角落標示「已完成」 |

前台在**鎖定名單後**才載入獎項與抽獎池（`stageLoad`），報到期間只顯示主頁，因此截止前對獎項的修改一定會反映在前台。

### 7.2 抽法與抽獎原理

| 抽法 | 第 1 次按「下一頁」 | 之後每按一次 |
|---|---|---|
| 一次抽完 | 所有格子依序停下（每格間隔約 0.5 秒） | 回到主頁（有作廢格時先補抽，見 7.3） |
| 逐個抽出 | 第 1 格停下 | 下一格開始滾動並停下，名字在同一頁累加；全部抽完後回到主頁 |

- 名字格式：`單位名稱_姓名`；同單位同名同姓時，自動加上工號後四碼，例如 `業務部_陳怡君（2345）`。
- 版面：1～5 位單欄大字，6～10 位雙欄；名字太長時自動縮小字級。
- 拉霸滾動的名字只從**目前抽獎池**取（已中獎、已作廢的人不會出現）。
- 每人限中一次；作廢的人不放回抽獎池。

**抽獎原理（README 附白話版說明）：**

1. 亂數來源：瀏覽器內建的 `crypto.getRandomValues`，密碼學等級，沒有種子、無法預測。
2. 把目前抽獎池 N 人編號 0～N-1，取一個隨機整數換算成號碼，以**拒絕取樣**消除取餘數造成的微小偏差，每人被抽中的機率完全相等（1/N）。
3. **按下「下一頁」的瞬間就決定結果**，立刻存進本機並送出寫入 Sheet；拉霸滾動只是動畫，滾過哪些名字與結果無關。
4. **不提供任何可調參數，也不提供「重新打亂」**。每次都是獨立的新亂數，事先洗牌不改變機率；系統沒有任何旋鈕，最容易說明公正性。
5. 不做權重。

### 7.3 按鍵

| 按鍵 | 功能 |
|---|---|
| `→` ／ `空白鍵` ／ `PageDown` | 下一頁、抽獎、補抽 |
| `←` ／ `PageUp` | 上一頁；在主頁時為回看已完成的獎項（已抽出的結果不能退回） |
| `X` | 作廢（見下方流程） |
| `1`～`9`、`0` | 作廢流程中選擇第幾格（`0`＝第 10 格） |
| `Enter` ／ `Esc` | 作廢流程中確認／取消 |
| `B` | 黑畫面切換 |
| `F` | 全螢幕 |
| `?` | 顯示狀態列（程式版本、前台代號、待同步筆數、素材狀態） |
| `F5` ／ `Ctrl+R` | 在抽獎頁與回看頁被攔截，不會重新整理 |

前台**只用鍵盤**，不支援滑鼠或觸控操作；點畫面只用來讓視窗取得鍵盤焦點。（原型為了在手機預覽，有「點舞台＝下一頁」與點格子作廢，正式版不做。）

| 目前所在頁面 | 按「下一頁」 | 按「上一頁」 |
|---|---|---|
| 主頁 | 進入下一個獎項的獎項頁 | 回看最近完成的獎項 |
| 獎項頁 | 進入抽獎頁 | 回到主頁 |
| 抽獎頁（還沒抽出任何人） | 抽出 | 回到獎項頁 |
| 抽獎頁（已抽出部分人） | 抽出下一位 | 無作用 |
| 有作廢且尚未補抽的名額 | 補抽該名額 | 無作用 |
| 獎項已全部抽完 | 回到主頁 | 無作用 |
| 回看頁 | 往主頁方向翻（最近完成的獎項若有待補抽名額，則為補抽） | 再往前一個獎項 |

**作廢流程（目前這個獎項）：**

| 步驟 | 按鍵 | 畫面 |
|---|---|---|
| 1 | `X` | 每一格左上角浮出小編號 1～10（逐個抽出只有 1 格已抽出時直接跳到步驟 2） |
| 2 | 數字鍵 | 該格出現淺色框，畫面最下方小字淡色顯示「作廢第 3 格：業務部_王小明？Enter 確認／Esc 取消」 |
| 3 | `Enter` | 名字變 30% 透明＋刪除線，標示「作廢」；下次按「下一頁」這一格重新滾動補抽 |

- **取消作廢**：補抽前，對已作廢的格子做同樣流程即恢復；補抽後不能再改。
- 作廢與取消作廢在本機處理，斷線時照常可用，結果與抽獎結果一起暫存、補寫。
- 「等多久算放棄」完全由主持人判斷，系統沒有任何計時器。

### 7.4 防呆與恢復

- 名字停下的動畫進行中，所有按鍵都不理會。
- 抽出就算數，要更正只能用作廢＋補抽。
- **同一時間只有一個前台作用中**：
  - 第一台開啟前台專屬連結的電腦自動成為作用中的前台，取得一組前台代號（存在該電腦瀏覽器，F5 後仍是同一台）。
  - 之後再開的前台顯示「另一台前台作用中，接手代號 4821」，須由後台選單「強制切換前台」輸入代號才會接手。**不做自動接手。**
  - 被取代的舊前台若之後恢復連線補寫，一律拒絕，記入操作紀錄並在控制台提示，由後台人員人工判斷（通常以台下已看到的結果為準，人工補登）。
- 名單快照的版本號或獎項檢查碼跟 Sheet 不一致時，前台拒絕抽獎，並提示重新載入。
- **斷線時繼續抽**：結果、作廢先暫存在本機，連線恢復後自動補寫；角落小字顯示「離線中，待同步 N 筆」（投影安全區外）。斷線期間控制台的「下一個獎項」「強制回主頁」傳不到前台，控制台顯示前台最後回報時間標紅。
- **進度保存**：抽獎進度與待同步結果即時存在瀏覽器本機儲存。誤按 F5（非抽獎頁）、瀏覽器當掉後重開，從本機儲存＋Sheet 恢復。
- **預載素材**：`stageLoad` 回傳素材清單後，前台**逐張**向 GAS 下載照片與背景圖（每張一次呼叫，失敗只重試那一張），字型同時預載；全部完成後狀態列顯示「素材已就緒 ✓」。照片由 GAS 從 Drive 讀出後回傳，Drive 檔案不需公開分享。
- 斷網時前台又當機：等網路恢復再重開，或用有網路的備用電腦開前台連結，由後台強制切換接手。
- 電腦整台故障：換一台電腦打開前台專屬連結，強制切換後從 Sheet 恢復進度。
- 啟用螢幕常亮；視窗失去鍵盤焦點時，角落顯示一個小提示點。
- 投影解析度不是 1920×1080 時，畫面依比例縮放並補邊（邊的顏色與主題背景同色）。
- 抽獎池人數不夠時，前台停住並提示，控制台跳出警告。

### 7.5 回看已完成的獎項

- 在主頁按 `←`，依序往回翻已完成獎項的公布頁（例如二獎 → 三獎 → 普獎）；按 `→` 往主頁方向翻回。
- 回看頁角落標示「已完成」，名字照原樣顯示，作廢的格子維持淡化。
- **只有最近完成的那一個獎項**可以作廢、取消作廢、補抽，期限到下一個獎項抽出第一位為止。用途是救回「前台太早回主頁」的狀況。
- 更早的獎項一律唯讀，按 `X` 沒有反應；這些獎項的問題依第 1 節「不在範圍內」人工處理。

## 8. 例外狀況處理一覽

| 狀況 | 處理方式 |
|---|---|
| 名單上沒有的人到場 | 人員分頁最下面加一列（登錄狀態：現場新增），請他自己掃碼報到 |
| 截止後才到、名單上沒有 | 同上，再由操作員按 `Ctrl + Shift + ;` 填報到時間（鎖定前） |
| 名單上的人不該參加 | 登錄狀態改「移除」（鎖定前） |
| 幫錯人報到 | 清掉報到時間（鎖定前） |
| 報到 QR code 被拍照外流、有人遠端報到 | 接受。被抽中時不在場，視同放棄，作廢補抽 |
| 得獎人不在場 | 主持人判斷等待時間後宣布放棄 → 前台作廢 → 前台補抽 |
| 作廢的人在補抽前趕回來 | 前台取消作廢 |
| 作廢的人在補抽後才出現 | 維持作廢 |
| 前台太早回到主頁，還有人要作廢 | 主頁按 `←` 回到最近完成的獎項作廢補抽（下一個獎項開抽前） |
| 更早的獎項事後發現問題（例如領獎時發現不是本人） | 沒收獎品、不補抽，承辦人在得獎名單備註欄人工註記 |
| 頒獎貴賓還沒到，要調整獎項順序 | 控制台指定下一個要抽的獎項 |
| 臨時加碼獎項或調整數量 | 截止報到前直接改獎項分頁 |
| 鎖定名單後才發現漏了人或獎項要改 | 開抽之前解除鎖定，修改後重新鎖定；開抽之後就無法處理 |
| 有人排序了人員分頁 | 報到寫入依工號找列，資料不會錯 |
| 有人刪了人員分頁的列 | 其他人不受影響；被刪的人若剛好在那幾秒內報到，時間寫不進去，Log 會記錄，人工補登 |
| 前台斷線 | 繼續抽，恢復後自動補寫 |
| 前台電腦故障 | 備用電腦開前台連結 → 後台強制切換 |
| GAS 單次請求失敗 | 前端自動重試；所有寫入 API 冪等，不會重複寫入 |
| 網路全面中斷 | 系統不處理，現場自行改用紙本 |
| 冒領 | 紙本券一人一張、不記名，領獎時收回；風險由主辦單位接受，系統不處理 |

## 10. 複用設計（給其他活動使用）

### 10.1 開一場新活動

**系統管理者：**

1. 點範本連結「建立副本」（GAS 程式會一起複製）。第一次建立範本時，改為在 Apps Script 編輯器執行一次 `setupTemplate` 建出所有分頁。
2. 「摸彩系統 › 活動前 › 初始化」：建立資料夾，照步驟清單部署 GAS，貼回部署 ID，等系統自動檢查通過。
3. 「摸彩系統 › 活動前 › 產生連結」：取得報到連結與 QR code、前台專屬連結。
4. 把 Sheet 共用給承辦人和後台操作員（編輯權）。

**承辦人：**

5. 填名單、填獎項、填設定、放主視覺 → 「摸彩系統 › 活動前 › 資料檢查」。

**系統管理者＋當天操作員：**

6. 彩排（見 6.3），同時陪每位後台操作員完成選單授權 → 「進階 › 清除資料」。
7. 活動當天：「活動當天 › 開始報到」。

### 10.2 兩種使用方式

| 方式 | 對象 | 說明 |
|---|---|---|
| 共用前端（預設） | 行政、福委 | 使用 steven 的 GitHub Pages，網址帶參數區分活動；可以固定在某個版本（例如 `/v1/`） |
| Fork | 會寫程式的人 | fork repo，修改設定檔和 CSS，部署到自己的 GitHub Pages |

**前後端版本相容：** `config` 回傳 API 版本號，前端發現與範本 GAS 不相容時顯示「此活動需使用 /v2/ 網址」，不會默默出錯。

### 10.3 原則

- 每場活動各自部署自己的 GAS，配額互不影響。
- 系統不寫死「春酒」「早教」等字眼。
- 每場活動的存取權由各自 Sheet 的共用設定決定，前台金鑰各自產生。
- GAS 專案時區固定 `Asia/Taipei`，不受複製者帳號時區影響。

### 10.4 Sheet 選單「摸彩系統」

見 6.1。

### 10.5 資料檢查的項目

重複工號、空白欄位、「可否摸彩」格式錯誤、登錄狀態空白、工號前導 0 遺失、找不到的照片（同時列出「素材」資料夾裡的實際檔名方便對照）、獎項數量 > 10、獎項總份數超過有資格人數、罕用字（可能沒有字型支援）、同單位同名同姓。

## 11. GAS 介面

### 11.1 Web API（給 GitHub Pages 呼叫）

| 動作 | 需要前台金鑰 | 開放時機 | 說明 |
|---|---|---|---|
| `config` | 否 | 已結束前 | 活動名稱、主題設定、系統狀態、API 版本號（不含名單） |
| `lookupId` | 否 | 報到中～已結束前 | 查工號，回傳遮蔽姓名、單位、抽獎資格、報到狀態；截止後對未報到者只回「報到已截止」；登錄狀態為移除者視同查無 |
| `checkin` | 否 | 報到中 | 確認報到；先記錄在 Script Properties 立刻回應，再批次寫入 Sheet（見 5.4） |
| `stageLoad` | 是 | 已鎖定之後 | 前台載入：獎項、抽獎池快照、已抽出與作廢的結果、素材清單、版本號與檢查碼 |
| `stageAsset` | 是 | 已鎖定之後 | 下載單一張照片或背景圖（由 GAS 從 Drive 讀出回傳） |
| `recordDraw` | 是 | 已鎖定之後 | 寫入一筆抽出、作廢或取消作廢；以「獎項＋名額序號＋動作」判斷，同一筆只寫一次；只接受目前作用中前台代號的寫入 |
| `heartbeat` | 是 | 已結束前 | 前台每幾秒回報狀態（頁面、待同步筆數、代號），並接收「下一個獎項」「強制回主頁」「已被取代」等指令 |

- POST 使用 `Content-Type: text/plain`，避免跨網域的 preflight 請求。
- **所有寫入 API 冪等**：重送一次不會產生重複資料（`checkin` 已報到則回傳原報到時間；`recordDraw` 同一筆已存在則直接回傳成功）。
- **每次請求只做一次寫入**，只有「寫了」或「沒寫」兩種狀態，不會留下殘缺資料。`checkin` 的一次寫入是待寫入清單；批次寫入 Sheet 可重複執行，結果相同。
- 另有 `ping`（不需金鑰、任何狀態）：只回傳 API 版本、Sheet 識別碼的雜湊值、時區，給「初始化」檢查部署用，不含活動資料。
- 每支 API 出錯時寫入 Log 分頁，並更新控制台的錯誤計數。

### 11.2 選單動作

由 Sheet 選單執行的伺服器端函式（見 6.1），以操作者本人的 Google 身分執行，與 Web API 共用同一個 GAS 專案，因此 LockService 的 Script Lock 能同時保護兩邊的寫入。每個選單動作在條件不符時，以白話說明原因與下一步（例如「請先截止報到，再鎖定名單」），不顯示程式錯誤訊息。

## 15. 前台原型設計規劃（交給下一個 session 實作）

> 這一節是第 0 階段「前台視覺原型」的完整規劃。下一個 session 照這一節製作即可，不用重新訪談需求。

### 15.1 原型的目的與範圍

- **目的**：在寫後端之前，先確認舞台的樣式和節奏；同時標示出所有可以客製化的區域，讓設計師照著出圖。
- **形式**：單一 HTML 檔，純前端、使用假資料，**不接 GAS 和 Sheet**。
- **交付**：
  1. 存一份到 repo 的 `prototype/stage-prototype.html`（雲端 session 無法寫入本機的 WeiClaudeFolder，需要時從 repo 下載）
  2. 發佈成私人 Artifact，讓使用者可以在投影機上開啟，也能轉給同事看
- **畫布**：固定 1920×1080 的舞台，等比例縮放到視窗大小，多出來的部分補邊（邊的顏色跟主題背景同色）。

### 15.2 風格原則

- **溫馨的馬卡龍色系**：用粉彩當大面積的色塊，但**文字一律使用深色**。投影機會讓淺色褪色，淺色字放在粉彩背景上，後排會看不到。
- **乾淨、留白多**：每一頁只放必要的資訊。不放燈籠、彩帶、星星、粒子、漸層光暈這類裝飾。
- **形狀語言**：大圓角（24～32px）、柔和的陰影（只用在名字格子和獎品照片上），沒有描邊框線。
- **動態克制**：只有拉霸本身有明顯的動態，換頁用 300～400ms 的淡入淡出加輕微位移，不做翻轉、飛入這類轉場。
- **不要俗氣**：不用大紅大金，也不用「恭喜發財」風格的字體。
- **不要科技感**：不用霓虹、深色底、等寬字、掃描線、數字雨。

### 15.3 配色主題（3 套，原型中按 `T` 切換）

每一套都定義相同的 6 個色彩 token：

| Token | 用途 | 草莓牛奶（預設） | 薄荷檸檬 | 薰衣草藍莓 |
|---|---|---|---|---|
| `--bg` | 頁面底色 | `#FFF5F3` | `#F3FAF6` | `#F6F4FB` |
| `--surface` | 名字格子、卡片 | `#FFFFFF` | `#FFFFFF` | `#FFFFFF` |
| `--primary` | 大色塊、獎項標題底 | `#F6B8C6` | `#A6DCC8` | `#C9BCEB` |
| `--secondary` | 輔助色塊、逐個抽的當前格 | `#B9E2D3` | `#FFE3A1` | `#B5D3F0` |
| `--ink` | 主要文字 | `#3E3236` | `#293F3A` | `#312E45` |
| `--ink-soft` | 次要文字（單位名稱、數量） | `#6E5A60` | `#4F6660` | `#595570` |

**對比要求：** `--ink` 放在 `--surface`、`--primary`、`--secondary` 上，對比度都要 ≥ 7:1（投影會降低對比，所以要保留餘裕）。上表是原型實際計算後調深的值（v1.1 的原始值 `#4A3B40`／`#8A7178`、`#2F4842`／`#5E7A72`、`#3D3A56`／`#6F6A8C` 對比不足）。

### 15.4 字型

| 用途 | 字型（Google Fonts） | 備用字型 |
|---|---|---|
| 標題、獎項名稱、得獎人姓名 | **Huninn**（粉圓體，圓體、溫暖） | `"Noto Sans TC", "Microsoft JhengHei", sans-serif` |
| 單位名稱、說明文字 | **Noto Sans TC**（400／500） | `"Microsoft JhengHei", sans-serif` |
| 數字（數量、報到人數） | **Nunito**（700，圓角數字） | Huninn |

- 製作前先確認 Huninn 可從 Google Fonts 載入（見第 14 節）。
- 罕用字：Huninn 的字集有限，缺字時會自動改用 Noto Sans TC 顯示。原型的假資料要放 2～3 個罕用字姓名（例如「堃」「㛃」「喆」），確認備用字型能接上，而且混用時不會太突兀。
- 字級（以 1920×1080 畫布為準）：

| 元素 | 字級 |
|---|---|
| 主頁活動名稱 | 120px |
| 主頁副標題 | 40px |
| 獎項頁獎項名稱 | 96px |
| 獎項頁數量 | 56px |
| 抽獎頁上方獎項名稱 | 56px |

```
│   ┌──────────────────────────────────┐       │

│   ┌──────────────────────────────────┐       │

│   └──────────────────────────────────┘       │

```
- 名額有幾份就畫幾格，安全區 1500×750 置中；1～5 格單欄，6～10 格雙欄（每欄 5 格）。

- 作廢：該格的名字變成 30% 透明度並加刪除線，旁邊標示小字「作廢」；下次按「下一頁」時，這一格重新滾動補抽。
- 作廢選格時：每格左上角浮出小編號；選中的格子出現淺色框；畫面最下方小字淡色顯示確認提示（見 7.3）。
- 右上角顯示進度「1 / 3」。
- **回看頁**：同公布頁版面，右上角進度改成「已完成」小標籤。

### 15.6 拉霸樣式（3 種，原型中按 `S` 切換）

| 樣式 | 視覺 | 停下的方式 |
|---|---|---|
| **A. 跳字** | 格子裡的名字快速替換（每 50ms 換一個），有輕微的上下位移 | 替換間隔由 50ms 逐漸拉長到 400ms，約 2 秒後停下，名字輕輕放大到 1.05 倍再回到 1 倍 |
| **B. 直向轉輪** | 格子像一個小窗口，裡面的名單由下往上連續捲動，上下邊緣淡出 | 用 ease-out 減速約 2.5 秒，最後一個名字對齊窗口正中央，稍微回彈 |
| **C. 翻牌** | 格子正面顯示「？」或主題色塊，背面是名字；滾動時只有色塊輕輕呼吸閃動 | 按下後卡片沿 Y 軸翻轉，露出名字（0.6 秒）。只有懸念感，沒有名字閃過 |

- 一次抽完：所有格子同時滾動，按下後**從第 1 格開始依序停下**，每格間隔 0.5 秒。
- 預設樣式為 A。
- 遵守 `prefers-reduced-motion`：開啟時改成淡入顯示結果。
- 動畫進行中，所有按鍵都不理會。

### 15.7 客製化區域標示（原型中按 `G` 切換）

按 `G` 時，在目前的頁面上疊一層**客製化標示圖層**：
